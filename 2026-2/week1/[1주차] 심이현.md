# 2026-2학기 1주차

* CGI(Common Gateway Interface): 1993년 서버가 html을 바로 만들기 위해 사용한 도구

* DB(Data Base)
  * Table
  * Query
  * Schem

* MVC: 웹 애플리케이션 구조를 역할별로 나눠 관리하는 설계 방식
  * Model: 데이터
  * View: 화면
  * Controller: model ⇔ view 연결

* API(데이터 공급자)
  * JSON: 데이터 형식
  * ENDPOINT: 창구 주소
  * CRUD: create / read / update / delete

* stateless: 서버는 각각의 요청을 독립적인 요청으로 처리&앞선 요청을 기본적으로 기억하지 않음. 따라서 별도의 상태 정보를 가지고 있지 않으면 해당 사용자가 누구인 지 알 수 없음 ⇒ 이를 해결 하기 위해 Session과 Cookie를 이용
  * session(서버 메모리에 저장) ⇒ 한계: 서버가 여러대 일 경우 관리 어려워짐  ⇒ 해결책: JWT(JSON web Token) - Header.Payload.Signature
  * cookie(웹 브라우저에 저장)

* non-blocking
  * Blocking: 한 작업이 끝날 때까지 다음 작업이 기다리는 방식
  * Non-blocking: 작업 요청 후 대기시간 동안 다른 작업 처리
    * 이벤트루프: 작업을 확인하면서 완료된 작업의 결과 처리
    * 멀티스레드: 여러개의 스레드를 사용해 작업 동시 처리

* 캐싱: 자주 요청하는 정보 DB대신 메모리에 저장하고 반환해줌
  * Time to live: 캐시에 올려둔 데이터의 유효기간
  * CDN(Content Delivery Network): 사용자의 위치와 가까운 서버에서 콘텐츠 전달

* Transaction & Scaling: ACID → ROLLBACK
  * 트랜잭션(ACID)
    * 원자성 / 일관성 / 격리성 / 지속성
    * 저눕 성공해야 커밋. 도중에 중단될 경우 즉시 롤백.

* 서버 확장
  * 수직확장: 서버의 성능 높이기
  * 수평확장: 서버를 여러대로 늘리기

* 마이크로서비스: 요청이 어디로 가야할 지 모름 → GateWay로 연결 / 메시지 큐를 사용하기도 함

* 배포
  * CI/CD: 자동 빌드 및 테스트 후 배포
  * Docker: 환경을 컨테이너로 묶어 관리
